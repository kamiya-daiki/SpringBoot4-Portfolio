## 技術スタック
### バックエンド
#### Java 21 (Spring Boot 4)
- バックエンドエンジニアとしてほとんどの大規模システムで採用されており、スキルとして非常に重要であることから採用しています。
- 過去のServlet/JSPやStruts/Spring frameworkの業務経験を活かせる点も採用理由です。

##### Spring Boot 3ではなく4を選択した理由
最初は3.5で技術検証をしていましたが、以下の理由でSpring Boot 4を採用しました。
- 既に4.xがリリースされており、Spring Securityなども更新されていたこと。
- 4.x系へ移行するように公式から促されていたこと（LTSの概念が無いため、3.4も2025年末までがサポート期限）
- 公式ドキュメント、チュートリアル等が4.x系をベースにしており、3.x系の最新版の情報自体が見付けづらく開発が難航する点。

### フロントエンド
**Thymeleaf + Bootstrap**
社内ツールのため、必要以上なフロントエンドの実装はしないことを意識しています。
フロントエンドはVueやTypescriptは採用せず、余力があったなどに学習を検討しています。
ページング処理等で非同期処理が必須と判断した場合には、基本機能が完成した後に機能追加（拡張）として実装することを考えています。

### データベース
**PostgreSQL**
クラウドのデータベースサービス（AWS、Azureなど）は個人開発としては費用や学習ハードルが高いため、PostgreSQLを採用しています。

### CI/CD	
**Maven + JaCoCo + GitHub Actions**
- Maven + JaCoCo … ポートフォリオの規模感からGradleは学習コストが高いと判断し、Mavenを採用しました。
- GitHub Action … 現代の開発環境として、特にチームで開発する上では必須スキルと考えています。

### コンテナ
**Docker / Compose**
現代の環境構築としてほぼ必須スキルではありますが、今回は自社を想定した社内システムのため余力のある場合に学習を検討しています。
ただしこれとは別に環境構築の手順書は作成することを前提としています。

### 認証
**Spring Security（JWT）**
Spring Bootのセキュリティシステムを採用しています。
(パスワードなどはBcryptにて暗号化した上でデータベースへ登録)
社内システムであることと学習コストの高さから、OAuth認証等は採用していません。

## 技術検証で意識したこと
- 苦手だった時間意識を改善するため、開発に着手する前に、根拠を持ってスケジュールを立てられるようにするため技術検証のフェーズを取り入れました。
- 現在のバックエンド開発現場を想定したメジャーな言語やツールなどを使い、実務に近い設計や実装、成果物を意識しました。
- Spring Boot学習時には個人のSpring Boot 3.xの記事などをかいつまんで学習するよりも公式のドキュメントやサンプルの豊富さから効率よく学べ、かつ将来のバージョンアップにも対応しやすいSpring Boot 4.x系を採用しました。
- システム完成後も保守や機能追加、マルチデバイス対応などが行いやすくなるように変更に強い設計、DTOやAPI中心設計を意識しました。
- ブランクは長いですが、現代のスキルを素早く身につけるためAIを活用し、しかしAIだけに頼って仕組みを理解していない実装にならないよう意識しながら学習を勧めました。
